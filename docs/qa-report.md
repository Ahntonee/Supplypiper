## Concordium accountability (2026-11-10)
**Defects found by testing (all fixed):** the first live probe showed the badge hash docs were ambiguous (resolved empirically); the listing returns no token address, so the verifier decodes and encodes addresses itself (round-trip checked against four real badge strings). A test used two "different" owners that were the same real account (test data, corrected). The EvidencePanel labelled the latest check "Last successful check", which would mislead after a failed recheck; it now shows both separately, asserted in the integration test.
**Mutation checks:** making approval reuse the cached verification made "a cached green result is never enough" fail (an order was created while the registry was down), then restored.
**Real-world observations that changed the design:** only 1 of 200 sampled testnet agents passes every badge check (83 match their hash but lack a valid badge), so a matching hash alone is `unverified`; a real on-chain agent URI is a `<script>` tag; a real card URL answers 404.
